# 操作手册生成器

将功能描述转化为结构化的操作手册，生成 .doc 文件保存到桌面；用户提供应用地址时自动截图嵌入。

## 工作流

### 第一步：追问到底

用户只给了菜单名、没有功能细节时，按序追问到信息完整：

1. 这个功能是干什么的？（一句话业务目的）
2. 谁用？（拖车公司/船代/货主/港区管理员/企业管理员）
3. 从哪个菜单进去？
4. 有哪些关键操作？（新增/编辑/删除/查询/审批/导入导出…）
5. 有没有特殊业务规则或限制？

**完成标准**：5 问已答，或用户提供了足够详细的功能描述（此时跳过追问）。

### 第二步：模板匹配

按功能类型选唯一模板：

| 功能类型 | 模板 | 原手册示例 |
|----------|------|-----------|
| CRUD 数据录入（含审批流） | A：数据录入+审批 | 车辆进港申请、人员信息录入 |
| 预约/调度类 | B：预约服务 | 送箱预约、提箱预约 |
| 绑定/配置类 | C：关联配置 | 协议车队绑定、人车绑定 |
| 查询/报表类 | D：查询服务 | 预约查询、库场查询 |
| 申报/导入类 | E：申报服务 | 船舶档案申报、船期预报 |
| 审批类（管理端） | F：审批管理 | 企业信息审批、车辆审批 |

**完成标准**：选定一个与功能类型对应的模板。

### 第三步：填模板

按模板逐段生成。`[占位符]` 用用户提供的信息替换；用户未提供的，按原手册通用惯例补全；不确定的业务规则标注 `[待确认]`，不要臆造。

**完成标准**：每个 `[占位符]` 已替换或标 `[待确认]`；每个关键操作都有对应章节。

### 第四步：生成 .doc 文件

将填好的模板内容整理为 JSON（格式参考 `references/schema.md`），用 `scripts/generate_docx.py` 生成 .doc 文件到桌面：

```bash
pip install python-docx Pillow 2>&1
# 网络慢时用清华镜像：pip install python-docx Pillow -i https://pypi.tuna.tsinghua.edu.cn/simple
python scripts/generate_docx.py .scratch/manual_data.json
```

注意：截图嵌入是可选项，只有在第五步执行过截图（或用户已有截图）时才在 JSON 中加 `image` 节点。纯文字版直接不加即可，不要留空图占位。

**完成标准**：桌面已生成 `<模块名>_操作手册.doc`，告知用户文件路径和文件大小。

### 第五步：截图增强（可选分支）

仅当用户提供应用访问地址**且**登录信息时执行。不提供则跳过，直接输出纯文字 .doc。

1. 先 `browser_resize(1920, 1080)` 再截图，否则宽弹窗被裁切。
2. 登录：填账号密码；验证码用 `browser_take_screenshot` 截取图片后请用户输入。
3. 按操作步骤从外到内截图：主页面 → 展开的筛选下拉框 → 新增/编辑弹窗 → 弹窗内下拉树 → 确认弹窗。标准模块 3-5 张，确认弹窗也值得截。
4. 按编号命名存到 `screenshots/`：`01_main.png`、`02_filter.png`、`03_add.png`…
5. 截图完成后，回到第四步把 `image` 节点补进 JSON 后重新生成 .doc。
6. EasyUI 兜底：
   - 下拉箭头点不中 → `browser_evaluate` 执行 `$('#id').combotree('showPanel')`
   - 弹窗遮罩残留 → `$('.window-mask').remove()`
   - 元素 ref 过期 → 先 `browser_snapshot` 再操作

**完成标准**：截图已嵌入 .doc 对应操作步骤下方；或明确告知用户未截图的原因。

## 模板

### 模板A：数据录入+审批

```
[序号]、[功能名称]

功能说明：用于[角色]进行[操作目的]。

[序号].1 新增
操作路径：[一级菜单] → [二级菜单] → 点击【添加】→ 输入[关键字段]（黄色选框为必填项）
→ [如有附件]上传[附件类型]（格式为 [格式]，大小 [尺寸范围]）→ 点击【保存】。
可对未[提交/审批]的[数据对象]进行【编辑】和【删除】处理。

【注意】：
（1）[关键约束1]
（2）[关键约束2]

[序号].2 提交[审批名称]
选中完成录入的[数据对象]，点击【[审批按钮]】完善申请信息，点击【提交】即完成
[数据对象]的[审批名称]。[到期时间等自动填写逻辑，如有]。

[序号].3 查看审批记录及[资质名称]
在"[审批记录/进港资质]"中查看审批进度。可对还未审批通过的信息进行【取消申请】，
对驳回信息更改后发起【重新申请】。若被驳回可选"查看流程图"了解驳回原因。

[数据对象]在[各维度]的[资质名称]可在"[资质查看位置]"中查看。

[序号].4 报停及删除
在[数据对象]需要停止[状态]时，对审批通过的记录进行【报停】处理。选择记录 →

⚠️ 审批记录中有"审批中"或"驳回"时不可删除，需先【取消申请】。

[序号].5 [特殊操作]
[描述]
```

## 写作惯例

模板未覆盖的写作约定：

### 标题层级

```
[汉字数字]、[章节名]操作手册（[角色]）    ← 一级
[数字]、[功能名]                            ← 二级
[数字].[数字] [子功能名]                    ← 三级
（1）（2）（3）                              ← 步骤
⚫                                            ← 列表
```

### 警告分级

- ⚠️：硬约束，违反则操作失败（如"审批中有记录时不可删除"）
- 【注意】：操作细节，容易忽略但不阻塞（如"只能修改一次"）
- （备注：...）：补充说明

### 通用用语

| 场景 | 用语 |
|------|------|
| 必填提示 | （黄色选框为必填项） |
| 检索提示 | 可通过输入拼音/英文首字母进行检索 |
| 操作成功 | 点击【保存】即完成... |
| 删除前置条件 | 需先将"审批中"及"驳回"的记录【取消申请】后才可删除 |
| 到期约束 | 申请的到期时间不可以超过附件的到期时间 |
| 附件格式 | jpg 或 PDF 格式，否则无法上传附件 |
| 长期附件 | 若附件为长期，请在"是否长期"一栏选择"是" |
