# 跨 skill 契约 — 与方法层的分工

## 分工

| | skill | 负责 | 不负责 |
|---|---|---|---|
| 调度层 | `ai-feynman-trigger`（本 skill） | 什么时候发起检验、归档拦截、生成命题、判断阶段形态 | 检验方法本身 |
| 方法层 | `ai-feynman-practice` | 怎么讲、怎么追问、盲区清单、验收标准 | 什么时候发起 |

**硬规则：本 skill 一个字都不重写检验方法。** 一律调用方法层。

## 为什么必须拆开

两者混在一起时会出现一个具体的故障：

「该不该检验」会被「怎么检验更顺手」污染 —— 于是永远选顺手的那条，于是永远不发起。

**调度层必须没有「顺手」这个选项。** 它只决定发不发起，不决定怎么发起。

**本skill 不修改方法层的任何文件。** 只调用。

## 调用契约

### 何时调用方法层

检验的**第 4 步（卡住）**之后。前面三步（拦截归档、生成命题、闭卷测试）由本 skill 完成。

```
归档拦截 → 生成命题 → 闭卷测试
                              ↓
                        卡住了？
                    ├── 否 → 停。不打分，不记录，不追问
                    └── 是 → 调方法层
```

### 调用时必须传递什么

方法层需要三项上下文，缺一项它的追问会跑偏：

| 传递项 | 例子 | 为什么必须 |
|---|---|---|
| **阶段** | 初中 | 决定人设与档位（温和档是12 岁小孩，毒舌档对小学生无效） |
| **命题原句** | 「判别式大于零就有两个实根」 | 方法层追问必须锚定具体句子，不能泛问 |
| **卡在哪一步** | 说不出它解决什么问题 | 决定盲区归类（术语空转 / 缺边界 / 事实错误） |
| **原创例子追问** | 「每次你举例子，额外问一句：这是你自己编的还是书上/网上看到的？」 | 方法层现有的三档追问**不会问这个**。不显式传，它就不问 |

### 原创例子追问为什么必须显式传

方法层的 `ai-guardrails.md` 是纯 AI 侧防幻觉的（三条约束针对 AI 的失败模式），**它不管学生例子的来源**。`three-tier-drill` 的三档追问也没有一条问「这例子哪来的」。

所以：**不传 = 不会问。** 这一条只存在于本 skill 的检验流程里，必须随调用传下去。

**为什么这一条值钱**：照搬能答对，改编就得握住结构。它不需要学生判断自己懂没懂，只需回答一个事实问题 —— 和举证式提问同一原理，「我觉得我懂了」挡不回来。

判定处理：

| 学生说 | 判定 |
|---|---|
| 自己想的 | 正常往下走 |
| 书上的 | **不算过** —— 记下来，要求现编一个 |
| 网上看到的 | 同上，且明确记「例子非自产，识别冒充生成」 |
| 「大概是书上那种，但我自己想的」 | 记下来。允许再编一个，但要比原来的更简单 |

最后一行是关键 —— **「大概」本身就是答案的一部分**。

## 调用前必须收窄范围

**方法层默认你给的是「一个概念」。学生给的是「一个章节」。直接传章节会展开成无限追问。**

### 收窄三问（学生主动检验时必走）

**第 1 问：拆板块**

> 光学三个板块：光的直线传播、反射、折射。你要测哪个？

理由：一次测一整章，学生会在第三轮放弃。**测完一个板块就能开始用**，这比测完整章更能坚持。

**第 2 问：压成命题**

选完之后再压一层：

> 折射这一块，用一句话说你认为的核心规则是什么？

**他说出来的那句话就是命题**，后面所有追问都锚在它上面。

**第 3 问：给不出命题怎么办**

**给不出本身就是答案** —— 说明他脑子里是一堆零散现象，没有结构。

此时**不硬测**，转`self-taught-learning` 从头理。硬测会把「没有结构」判成「某几个点不懂」，方向就错了。

### 收窄原则

> **范围永远是「一句命题」，不是「一个章节」。**

### 事件触发时的收窄

事件触发（R1-R5）自带命题 —— 错题、老师原话、决策依据。**不需要收窄**，直接抄。

只有「用户主动要求检验一个领域」这一种情况需要走上面三问。

### 档位建议（可被方法层覆盖）

| 阶段 | 建议档位 |
|---|---|
| 小学 | 温和 |
| 初中 | 温和 → 苏格拉底 |
| 高中 | 温和 → 毒舌 |
| 大学 | 苏格拉底 → 毒舌 |
| 研究生 | 毒舌 |

**注意「小学 → 温和档」不是降级，是适配**：温和档的人设（只懂加减乘除的小孩）与小学生的认知形态接近，毒舌档对小学生只会造成羞耻而不产生洞。

### 不得传递什么

**不传「用户觉得自己懂多少」。** 那是裁决权，属于外部。传了等于把判断权交回给用户。

用户说「我很懂」→ 按 R3 处理，不作为上下文传给方法层。

## 方法层不可用的降级路径

若方法层未安装或加载失败：

1. **先按查找序确认**（`.config\opencode` → `.claude` → `.cc-switch`）。多半不是丢了，是被 cc-switch 搬了位置。
2. 三个位置都没有 → 明确告知用户「检验方法层未加载，本 skill 只负责发起，不负责检验方法」，并给出上节查找序供参考。
3. 仍然完成前两步（归档拦截 + 命题生成）—— 这两步本身有价值，且不依赖方法层。
4. 卡住之后停下，产出「待检验清单」交给用户手动处理。
5. **不自行编写检验流程。** 那是方法层的职责，重复实现会造成两套不一致的验收标准。

## 一致性约束

本 skill 引用以下方法层术语，含义以方法层的 `references/glossary.md` 为准：

- **假懂** —— 自以为懂，被追问才暴露
- **打圆场** —— 把理解漏洞归因为表达瑕疵
- **盲区清单** —— 四分类：事实错误 / 逻辑跳跃 / 术语空转 / 缺边界
- **真懂验收标准** —— 清单清零 + 间隔复测 + 30 秒讲清 + 扛住两个追问 + 独立度
- **护栏** —— AI 不是真理机，三条约束

**本 skill 不修改这些定义。** 若发现方法层定义与本 skill 冲突，以方法层为准，并提示用户。

## 反向依赖检查

方法层的 description 全部是「我以为我懂了但讲不清」「怎么知道自己不是在自欺」——**全部预设用户已自知**。

这正是本 skill 存在的理由：给方法层补一个从外部发起的入口。

**所以本 skill 不是方法层的替代品，是它的前置。** 用户说「我早就懂了」时，本 skill 先接住，把 R3 转成方法层能处理的格式（命题 + 卡点），再交给方法层。

方法层单独使用时仍有原来的缺口 —— 那是有意保留的，因为补它需要改动方法层，而本 skill 不动方法层。
