# ai-feynman-trigger — 检验的调度层

## 这个 skill 做什么

| | 负责 | 不负责 |
|---|---|---|
| **本 skill**（调度层） | 什么时候发起检验、归档拦截、生成命题、判断阶段形态 | 检验方法本身 |
| `ai-feynman-practice`（方法层） | 怎么讲、怎么追问、盲区清单、验收标准 | 什么时候发起 |

**本 skill 一个字都不重写检验方法。** 一律调用方法层。详见 `references/cross-skill.md`。

## 核心问题

费曼法只在「我已经怀疑自己不懂」时才被启动。但「不知道自己不知道」恰恰是唯一不会触发它的盲区。

后果不是「不懂」，而是**知识停在"认得出"这一层**，然后在真要用的时候崩，且因为自信而不归因于知识。

```
感觉良好 → 不发起 → 停在认得出 → 落地失败 → 不归因于知识 → 感觉仍然良好
```

这条路径不依赖意志力，所以靠「提醒自己要谦虚」无法对抗。

## 加载后先判定，再回答（半主动闸门）

**本 skill 是半主动的**：被动加载，但加载后不立刻回答，先检查该不该检验。

不要问「你懂吗」——那个问法在语法上邀请借口。改为检查客观信号。

```
G1  一手信号已发生？错题 / 被纠正 / 成绩形状异常 / 卷面痕迹
    → 立即检验（证据在体外，逃不掉）

G2  正在落地？用户正要写 / 讲 / 做决策 / 交作业
    → 插一句检验，不等用户开口

G3  两者都没有
    → 正常回答。不检验。不提本skill。

G0  用户主动要求检验（「我想测下…」「帮我检验…」「考考我」）
    → **先收窄到一句命题，再调方法层**。不走归档拦截。
```

**硬规则：**
- **每次只推一条**，绝不列清单。列清单会导致整体跳过。
- **G3 必须沉默。** 用户只想问个问题，就直接答。
- **不打断与检验无关的事。** 检验只在「已经要投入」的时刻插，成本才最低。
- **用户主动要求检验时不受频率限制。**

## G0：主动检验怎么接

**用户自己就是触发器，所以调度层的全部工作都不需要。**

没有失败要拦截 → 不套`archive-correction.md`（无端指责会把人推走）。
有现成的命题可抄吗 → 没有，得AI 出。**所以必须先收窄。**

```
1. 拆板块   光学三个板块：直线传播/反射/折射。测哪个？
2. 压成命题 这一块，用一句话说核心规则是什么？
3. 传四   阶段 + 命题原句 + 卡点 + 原创例子追问
```

**第 3 步给不出命题 → 不硬测。** 说明脑子里是零散现象没有结构，转`self-taught-learning` 从头理。

**范围永远是「一句命题」，不是「一个章节」。**

细节见 `references/cross-skill.md`。

## 两个必须显式传给方法层的东西

方法层的护栏卡只管AI 侧的幻觉，**不管学生例子的来源**。以下两条不显式传，方法层就不会问：

|传递 | 内容 |
|---|---|
| **原创例子追问** | 「每次你举例子，额外问一句：这是你自己编的还是书上/网上看到的？」照搬能答对，改编就得握住结构。 |
| **档位建议** | 小学 → 温和；初中 → 温和→苏格拉底；高中 → 温和→毒舌；大学 → 苏格拉底→毒舌；研究生 → 毒舌 |

**不传原创例子追问 = 方法层的追问只测生成，不管识别冒充生成。**

## 首次触发：问阶段

只在会话内第一次需要检验时问一句：

> 你目前是哪个阶段？（小学 / 初中 / 高中 / 大学 / 研究生）

拿到后**会话内记住，不再问**。用户主动说明阶段时不复述、不确认。

阶段决定检验的具体形态，见 `references/stage-protocols.md`。

## 检验的标准动作（四步）

1. **拦截归档** —— 把「我不会」从非概念原因拉回概念原因。见 `references/archive-correction.md`
2. **生成命题** —— 按阶段退化：抄 → 改写 → 自造。见 `references/proposition-ladder.md`
3. **识别 vs 生成** —— 闭卷，不看材料。核心区分：识别（看懂）易，生成（讲出）难。主观感受只能证明前者。
4. **卡住就升级** —— 任何一步卡住 → 交给方法层。不打分、不评级、不判真懂假懂。

**没有通过标准。** 「卡住」是二值可观测的，不是分数。

> 「卡住 → 升级」与「完全不打分」是同一件事：「卡住」不是质量分。

## 五条触发规则

详见 `references/trigger-rules.md`。

| | 触发 | 证据在哪 |
|---|---|---|
| R1 | 用砸了：依赖的说法在现实里不成立 | 现实结果 |
| R2 | 被纠正：别人把它指出来了 | 别人 |
| R3 | **「我早就懂了」，且后面跟着一个具体的东西** | 用户说的 |
| R4 | 输出：要把这个讲给别人或写下来 | 产出物 |
| R5 | 决策：用这个说法做取舍，且取舍有代价 | 决策记录 |

**R3 是对本 skill 存在理由的直接回答。** 它是唯一在无自觉状态下仍在场的信号：

- 出现得最准 —— 只在真实理解的薄弱区最强
- 不需要承认任何事 —— 触发动作是「持有信心」，不是「承认无知」
- 自带正反馈 —— 说出「我早就懂了」很舒服，顺手检验 30 秒不构成负担

## 两条不能省的规则

**一、不给借口留插槽。** 拦截靠提问形式，不靠识别。举证式提问：「用一句话说出来」「换个条件还成立吗」「凭什么」。**「粗心」回答不了「用一句话说出来」。**

**二、强制发起，不降低门槛。** 本skill 强制的是「发起检验」。方法层的验收标准一字不改。若允许用「降低标准」换「不用检验」，机制立刻失效。

用户要「降低标准」或「别检验了」→ 不执行。可降的是频率，不是门槛。

## 边界

- **要做能力排名、打分、评级** → 不做。一打分就变应付。
- **要把 AI 当知识源查证事实** → 交给方法层护栏，外部事实须人工查证。
- **用户要的是「学新东西」而不是「检验已有理解」** → 转常规学习路径，不套本 skill。
- **低置信时不强制** —— 「我不太确定这个有没有洞」→ 不触发。宁可漏，不可天天误伤。
- **用户情绪危机或需专业辅导** → 不套本 skill。

**假阳性成本必须计入。** 强制检验会浪费一部分真懂的人。总开销 = 假阳性率 × 单次成本。所以低置信不触发，且只在真要落地时才开口。

## 明确不做

- 不建台账/ 状态位文件 —— 没人维护的台账比没有更糟，它提供虚假的「已验证」安全感
- 不建日历排期 —— 节拍器是课本章节，外部且现成
- 不做随机抽样 —— 依赖台账
- 不打分、不排名、不评级
- 不做自动检测 —— 检测工作流需要 harness，个人学习场景没有
