# 自学闭环总控（Learning Loop）

> 一句话：把"规划 → 备料 → 编排 → 讲/练 → 校对 → 验收 → 发布 → 长期推进"串成一条线，每一步交给对应的能力卡执行；练习与验收交给现有 `ai-feynman-practice`。

## R — 原文 (Reading)

> "费曼学习法有四步：找材料、写讲稿、审核校对、复盘总结。"
> — 第211期

> "你可以用费曼学习法拿来复习，超前学习法拿来预习……也可以预习和复习相结合，就统一用费曼学习法。"
>
> "共同基础是日拱一卒。"
> — 第18讲

## I — 方法论骨架 (Interpretation)

本卡是**调度卡**，不重复各环节细节，只负责判断"用户现在处于哪一步、该调用哪张卡"。

完整闭环（8 步）：

| 步 | 做什么 | 交给谁 |
|---|---|---|
| 1 规划 | 定超前范围、目标、深度分层 | `frontier-planning` |
| 2 备料 | 找教材、定前置、挑重点 | `material-pipeline` |
| 3 编排 | 决定讲什么、顺序、每个概念的动机 | `content-orchestration` |
| 4 讲 / 练 | 写讲义并讲；被追问、暴露盲区 | `content-orchestration` 产出 → **`ai-feynman-practice`（三档陪练）** |
| 5 校对 | 纠错、补充、查跨书定义冲突 | `material-pipeline` |
| 6 验收 | 判"是否真懂 / 是否学会" | **`ai-feynman-practice`（mastery-acceptance）** |
| 7 发布 | 拿真实反馈、定位重难点 | `publish-and-feedback` |
| 8 长期推进 | 日拱一卒、动机供给 | `motivation-engine` |

**贯穿全程**：动机供给（`motivation-engine`）不是某一步，而是支撑整条闭环。

**与现有 skill 的分工**：本 skill（`self-taught-learning`）负责"学什么、怎么准备、怎么产出、怎么拿反馈"；现有 `ai-feynman-practice` 负责"练得对不对、算不算学会"。两者前后接续，不重复实现。

## A1 — 讲者案例 (Past Application)

### 案例 1：点集拓扑学的完整闭环（第12讲，亲述）
- 规划/备料：听不懂课 → 自己决定重排知识点
- 编排+串讲：从头整理成自己的讲义
- 讲/练：把整理的内容讲给别人
- 结果：期末 97 分，且此后多门课越学越好
- 说明：这条闭环不是四步孤立的，而是"自己当老师"贯穿始终

### 案例 2：预习 + 复习的统一（第18讲）
- 超前学习法（预习）+ 费曼学习法（复习）可分开可统一；共同基础是日拱一卒

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个能力？
1. 「我想系统学一门课/一个领域，但不知道从哪开始、按什么步骤走」
2. 「我已经在学了，但不知道下一步该做什么」
3. 「感觉学得没章法，东一榔头西一棒子」
4. 「想把学习方法整合成一套流程」

### 语言信号
- "我想系统自学 X / 不知道从哪开始"
- "学习流程 / 学习步骤 / 怎么安排整个学习过程"
- "接下来该做什么"
- "a system / workflow for learning X"

### 与相邻能力的区分
- 本卡是**入口调度**：用户问题明确指向某一步时，直接调用对应卡，不套全流程。
- 与现有 `ai-feynman-practice`：本卡在"讲/练""验收"两步显式转交给它。

## E — 可执行步骤 (Execution)

0. **判断用户所处环节**（不要一律从头跑）
   - 问清：想学什么、目前进度、卡在哪
   - 完成标准：明确落到下面 1-8 的某一步（或连续几步）

1. **规划** → 调用 `frontier-planning`
   - 定范围（一门）、目标、深度分层、日拱一卒计划

2. **备料** → 调用 `material-pipeline`
   - 选主线教材、定前置章节、圈重点

3. **编排** → 调用 `content-orchestration`
   - 列大纲、给每个概念配动机、串讲重排

4. **讲 / 练** → 产出讲义后，转 `ai-feynman-practice`
   - 用三档陪练（温和 → 苏格拉底 → 毒舌）暴露盲区，产出盲区清单

5. **校对** → 回到 `material-pipeline` 的审核校对步骤
   - 纠错、补比喻、查跨书定义冲突

6. **验收** → 转 `ai-feynman-practice`（mastery-acceptance）
   - 盲区清单清零 + 间隔复测 + 30 秒讲清 + 扛住追问

7. **发布** → 调用 `publish-and-feedback`
   - 小体量起步、低姿态、收集具体反馈、定位重难点

8. **长期推进** → 调用 `motivation-engine`（日拱一卒 / 有限-无限游戏 / 抗遗忘的**唯一归属卡**，此处仅转交）

**完成标准**：① 用户所处环节被正确识别，其对应卡的完成标准达成；② 至少走完"规划 → 产出 → 练习/验收"完整一轮，且验收环节**实际接入了 `ai-feynman-practice`**（不能只走流程不验收）；③ 一轮结束给出一句"下一轮把上游推哪一格"的建议。

## B — 边界 (Boundary) ★

### 不要在以下情况使用此能力
- **用户只问某一步**（如"怎么推荐教材"）：直接调对应卡，不要强推全流程
- **需要的是学科知识本身**：本卡只给学习流程，不传授学科内容
- **要"从零系统学会一门新学科"的常规路径**：本卡用于方法论调度，具体学科学习仍需常规手段

### 作者警告的失败模式
- **东一榔头西一棒子**：没有主线与顺序，学得散
- **跳过验收**：讲完就算学会（应转 `ai-feynman-practice` 验收）
- **跳过校对**：把跨书定义冲突固化成错的长期记忆

### 作者的盲点 / 局限
- **闭环充分性未验证**：8 步是从 4 讲综合而成，讲者本人未以"闭环"形式完整呈现过
- **学科局限**：案例均来自数学
- **与现有 skill 的边界**：需靠触发词分工，避免两个 skill 对"费曼"关键词重复触发

### 容易混淆的邻近方法论
- `ai-feynman-practice`：只管中段的"练与验收"；本卡是跨全部环节的调度
