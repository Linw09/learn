# 讲义内容编排（Content Orchestration）

> 一句话：写讲义/讲一门课之前，先站到老师视角决定"讲什么、按什么顺序讲、每个概念为什么现在讲"——把知识排成一条初学者能跟着走的线。

## R — 原文 (Reading)

> "首先成为一个好老师，其次才能成为一个好学生。"
>
> "从老师的角度来看，一定要照顾学生……一个是知识层面，还有一个是心理层面的照顾。"
> — 第107讲

> "你每次要讲一个新的概念，你一定要有动机，为什么要讲、讲清楚。"
>
> "我是先定义了向量……我说向量我直接抛出一个问题，完全是开放性问题，叫做'向量有什么运算'……然后说'先做标量乘法可以吗？可以。再相加可以吗？可以。这就是线性组合'，你看就非常自然。"
> — 第107讲

> "知识点本身的结构是网状的……一定要排成一条线，因为时间是一条线……要从无序的东西当中找到它的一个序，这就是教学的核心难点。"
> — 第12讲

## I — 方法论骨架 (Interpretation)

内容编排是费曼法"讲之前"的准备工程。核心立场：**先成为好老师，才能成为好学生**——自学者必须自己决定学什么、按什么顺序学；只当学生＝执行者，不知道为什么这样安排，也就无法判断安排是否合理。

五个操作原则：

1. **照顾学生 = 知识层 + 心理层**
   - 知识层：先判断学生学过什么、这门课需要什么前置，再决定"衔接部分放多少"
   - 心理层：别做端着的名词党，态度上贴近学生
2. **每个新概念都要配动机**：从历史/猜想引出，或用一个开放性问题引出（"向量有什么运算"→标量乘→相加→线性组合）。反面：直接抛定义（"线性组合就是存在一些标量相乘再相加"，太死板）。
3. **从最简单处讲起**：从对方能接住那一级台阶开始；顺序是通俗易懂 → 深入浅出 → 简单到难 → 具体到抽象（此顺序链出自第12讲）。
4. **串讲**：不照搬任何教材顺序，打乱后用自己理解的次序重排。核心矛盾是"知识是网状的（无序），而讲授必须线性（全序）"——串讲就是在这两者间做有意识的重排。
5. **以理解为核心 + 反竞速 + 反完美主义**：怎么排只看"是否更容易理解"；不比进度，不追求一步到位的完美（否则进度极慢）。

**前置知识是相对的**：学黎曼几何前置是微分流形，做筛法前置变成解析数论——写讲义前先确定"为这个目标要补哪一段衔接"。

## A1 — 讲者案例 (Past Application)

### 案例 1：线性代数——用"向量有什么运算"引出线性组合（第107讲，亲历）
- 做法：先定义 Rⁿ 向量 → 抛开放问题"向量有什么运算" → 学生答"加法""乘法" → 顺势引出标量乘、内积 → 问"先标量乘再相加可以吗" → 自然得出线性组合
- 结论：把死板的定义换成一个开放问题，学生自然跟着走
- 迁移：遇到"李群"这类更难对象，同样问"群与群之间有同态、流形之间有光滑映射，那李群之间有什么"，自然引出结构问题

### 案例 2：前置知识随目标而变（第107讲，亲历）
- 学黎曼几何 → 前置换微分流形；做筛法 → 前置换解析数论
- 结论：没有唯一正确的学习顺序，前置由目标决定

### 案例 3：选课数据侧面验证（第107讲，亲历）
- 同期的线性代数二班两周内从 130+ 退到 100+；讲者的班从 80 涨到 105（waitlist 挤满）
- 结论：照顾学生、给概念配动机的编排能留住并吸引学生（讲者自述，未提供第三方核验）

### 案例 4："什么算学好了"（第107讲，演示）
- 标准是"随便问一个都能知道，还能讲一讲、能串起来"（例：讲清同调与上同调的区别——上同调有环结构、对偶需特定条件）
- 配套口径：本科一学期真正学好两门课就很了不起

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个能力？
1. 「我要写一份讲义 / 讲一门课，怎么安排内容」
2. 「我照着教材讲，学生/自己觉得枯燥听不懂，怎么改」
3. 「怎么给一个抽象概念讲清楚 / 怎么引出它」
4. 「我照搬别人的顺序总觉得别扭，想按自己的理解重排」
5. 「我想把这门课的知识串起来讲」

### 语言信号
- "讲义怎么写 / 内容怎么排 / 讲稿怎么组织"
- "怎么引出这个概念 / 怎么讲得让人听懂"
- "串讲 / 重新编排 / 打乱教材顺序"
- "怎么照顾初学者"
- "how to structure my notes / how to teach this concept"

### 与相邻能力的区分
- 与 `frontier-planning`：规划卡决定"学什么、学到多深"；本卡决定"怎么把它讲出去"。
- 与 `ai-feynman-practice`（现有 skill）：本卡负责"讲之前把料备好、排好"；"讲完怎么被追问、怎么验收"交现有 skill。
- 与 `material-pipeline`：备料卡解决"用哪本书、查不查错"；本卡解决"顺序与动机设计"。

## E — 可执行步骤 (Execution)

1. **切换到老师视角**
   - 明确：这门课/这份讲义，我（作为老师）要让学生达到什么
   - 完成标准：能用一句话说出"讲完之后学生应该会什么"

2. **判断受众基础与前置**
   - 列出学生已会的、这门课需要的；确定要补的衔接内容
   - 完成标准：一份"前置/衔接清单"（放多少视讲义范围而定）

3. **给每个新概念配动机**
   - 对每个核心概念，写出"为什么现在讲它"：历史/猜想引出，或一个开放性问题引出
   - 完成标准：每个核心概念都有一个引子，且引子能自然过渡到定义

4. **从最简单处起步**
   - 检查起点是否在受众能力之上、又能被接住；避免"从自己也没搞懂的中间处开讲"
   - 完成标准：开头三分钟能让零基础的人跟上

5. **串讲重排**
   - 画出知识之间的关系（网状），再排成一条讲授线（全序）；可打破教材原有顺序
   - 完成标准：得到一份"自己的"大纲，而非目录照抄

6. **写出来**
   - 按大纲写出讲义；顺序遵循简单→难、具体→抽象
   - 完成标准：初稿完成（可用 `material-pipeline` 校对）

7. **自查是否照顾到学生**
   - 知识层：前置补了吗？心理层：有没有端着/堆术语？
   - 完成标准：能指出每个难点旁边"我给学生的台阶"是什么

## B — 边界 (Boundary) ★

### 不要在以下情况使用此能力
- **你自己都还不懂这块内容**：本卡是"怎么讲"，不是"怎么懂"——先学（用 `frontier-planning`）再编排
- **纯应试、按考纲划重点即可**：本卡追求理解，不是考点清单
- **要求一步到位的完美讲义**：作者明确反对完美主义拖慢进度

### 作者警告的失败模式
- **名词党式教学**：用术语堆砌显示"我懂得多"，学生讨厌（第107讲）
- **照搬教材顺序**：书可能故意或无意写得难懂；不重排就讲不顺
- **按教材权威压自己**：旧经典不一定适合初学者，教科书数十年翻新一次
- **竞速贪多**：一学期铺开很多课，结果都没学透
- **从"自己也没搞懂的中间起点"开讲**：必定失败且彻底

### 作者的盲点 / 局限
- **学科局限**：案例全部来自数学/理论学科，对技能型、实践型内容未验证
- **"选课数据"为自述**：80→105 人的数据无第三方核验
- **"照顾学生"缺少具体阈值**：衔接放多少、详略如何定，靠讲师经验判断

### 容易混淆的邻近方法论
- **抄笔记 / 整理笔记**：那是记录；本卡是"为讲给别人而做的编排"，目的不同
- **教材目录**：那是别人的顺序；串讲恰恰要求重排
- **讲砸后的事后复盘与归因**：若内容已经讲出去、翻车了（"学生说听不懂"要追因），转 `ai-feynman-practice`；本卡只管**事前**的编排与表达
