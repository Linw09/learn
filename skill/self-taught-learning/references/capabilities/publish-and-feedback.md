# 发布与反馈管理（Publish & Feedback）

> 一句话：把"讲给假想学生"升级成"讲给真实学生"，用真实反馈把"学过"变成"学会"——但起步要小、姿态要低、反馈要具体。

## R — 原文 (Reading)

> "你先教假想的学生，教会了以后，将来你总要真正去教学生……真实的教学环境，你这个信心增长的速度远远超过假想的人。"
>
> "一定是要夸的要具体，批评的也要具体，哪里不好也要说出来，这样彼此之间会产生高价值的反馈。"
>
> "哪怕一个菲尔兹奖得主给你写了一句'这个学生数学学得还不错'，这句话等于废话，还不如一张白纸。"
> — 第12讲

> "第一次只录十节课、单个约半小时，别开 100 小时大系列、别留坑。"
>
> "标题谦虚（写'自用''第一次讲''有错请指出'）……受不了就别发，其次关评论，再其次删恶心评论。"
> — 第211期

## I — 方法论骨架 (Interpretation)

自学最缺的是"真实反馈"。发布是把假想听众换成真实听众的手段，但需要一整套风险管理与反馈筛选机制：

1. **假想学生 → 真实学生**：先对假想听众练，再发到真实场景（平台/讨论班/学习小组）。真实反馈的价值：**判断重难点**——学生一学就会的地方可略讲，怎么讲都不懂的地方就是难点；且真实信心的增长速度远快于自我演练。
2. **小体量起步**：第一次只做十节左右、每节约半小时，别开大系列、别留坑。降低"烂尾"风险。
3. **低姿态发布**：标题写"自用""第一次讲""有错请指出"，降低被攻击面（案例：朋友改标题后骂声骤减）。
4. **反馈管理**：受不了就别发；其次关评论；再次删掉恶意评论。长期做需要**现实中的朋友**给真实反馈。
5. **高价值反馈标准 = 具体**：夸要夸到点子上，批评也要说清哪里不好。泛泛评价（"还不错"）等于废话，不产生改进。
6. **讨论班形态**：一群人互相教、互相听、互相给具体反馈；需共同价值观（长期主义），避免破坏氛围。

## A1 — 讲者案例 (Past Application)

### 案例 1：B 站 100 个粉丝用了三个月（第12讲，亲述）
- 早期一天加一个粉丝；后来说明"现在每天有 100 人来看"
- 结论：当下找到真实听众很容易，不必只对着假想学生

### 案例 2：朋友"银河"改标题后骂声骤减（第211期，转述）
- 内容不变，只把标题改得更谦虚，负面反馈明显减少
- 结论：姿态影响反馈质量

### 案例 3：观众反馈"开了讨论班后看书不累了"（第12讲，转述）
- 结论：讨论班＝互相教学的环节，能改善状态

### 案例 4：菲尔兹奖得主的空话评语 = 废纸（第12讲，演示）
- 结论：反馈的价值取决于具体度，与来源权威无关

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个能力？
1. 「我想把学到的东西讲出去 / 做内容，怎么起步」

3. 「怎么让别人给我有用的反馈，而不是客套」
4. 「一个人学太闷，想找人一起学」
5. 「怎么知道自己讲得好不好」

- "怎么拿到真实反馈 / 没人给我反馈"

## E — 可执行步骤 (Execution)

1. **确定小体量起步范围**
   - 第一批只做十节左右、每节约半小时；不追求大而全
   - 完成标准：范围小到"能做完、不留坑"

2. **先定发布暴露级别，再低姿态发布**
   - 发布前先按心理承受力选暴露级别（四档递进）：受不了就先不发 → 只发给朋友 → 公开发但关评论 → 完全公开
   - 标题写清"自用/第一次讲/有错请指出"，降低攻击面
   - 完成标准：暴露级别已选定 + 标题不含"权威口吻"

3. **选择发布渠道**
   - 平台 / 学习小组 / 讨论班，任选能持续获得真人反馈的
   - 完成标准：明确一个渠道并完成第一次发布

4. **收集反馈**
   - 主动请人具体反馈：哪里讲得好、哪里不好
   - 完成标准：收到至少一条具体反馈（而非"还不错"）

5. **按"具体性"筛选反馈**
   - 具体 → 采纳；空泛 → 忽略；情绪化恶评 → 删除或屏蔽
   - 完成标准：把反馈分成"可行动/不可行动"两类

6. **用反馈定位重难点**
   - 学生秒懂处 → 精简；怎么讲都不懂处 → 标为难点，重新设计讲法
   - 完成标准：产出一份"重难点清单"

7. **用事前定好的级别管理负面反馈**
   - 依第 2 步选定的暴露级别应对：关评论 / 删恶评 / 退回只发朋友；长期靠现实中的朋友支撑
   - 完成标准：负面反馈的处理有既定规则可依，不临场硬扛

8. **迭代翻新版本**
   - 用真实反馈改进，但不为流量牺牲内容本质（内容为本，流量为末）
   - 完成标准：产出下一版，而非推倒重来

## B — 边界 (Boundary) ★

### 不要在以下情况使用此能力
- **你不想公开**：发布只是获取真实反馈的手段之一，不是必须；可用学习小组/朋友替代
- **内容还不成熟且心理脆弱**：先对假想学生或 AI 练（`ai-feynman-practice`），再公开
- **把发布当成目标本身**：作者明确"内容为本、流量为末"，不要为数据改内容本质

### 作者警告的失败模式
- **开局就开大系列**：100 小时大坑，容易烂尾
- **高姿态标题**：招致攻击与无谓消耗
- **把空泛反馈当反馈**：得不到改进信号
- **硬扛负面评价**：被流量环境伤害而不设止损
- **为碾压别人而发布**：滑向内卷（第18讲）

### 作者的盲点 / 局限
- **平台环境差异**：作者的经验基于 B 站/数学圈，其他领域未必适用
- **涨粉数据为自述**：无第三方核验
- **工具链时效**：录屏工具链（Notability/QuickTime/OBS）不纳入本卡
- **未讨论失败代价**：公开发布对心理的负面影响，作者只给了简单止损规则

### 容易混淆的邻近方法论
- **做自媒体 / 涨粉**：本卡目的是"获取真实反馈以学会"，不是运营账号
