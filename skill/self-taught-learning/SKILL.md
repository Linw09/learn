# 自学闭环（Maki 学习方法四讲）— 能力入口

> 来源：B站 UP 主 Maki「认知小讲座」第12讲《费曼学习法》、第18讲《超前学习法》、第107讲《再谈费曼学习法·编排内容》、第211期《如何用AI辅助费曼学习法》。

## 与 ai-feynman-practice 的分工（先看这里）

- **本 skill（self-taught-learning）**：怎么**规划**学什么、怎么**备料**、怎么**编排**、怎么**持续**、怎么**发布拿反馈** → 上游 + 外围
- **ai-feynman-practice**：怎么**练**、怎么判断**真懂/学会**（三档陪练、盲区清单、验收标准） → 中段 + 验收

用户问"我想怎么学 / 从哪开始 / 讲义怎么写 / 学不下去" → 本 skill。
用户问"帮我练 / 考我 / 我是不是真懂了 / 验收" → 转 `ai-feynman-practice`。

## 核心原则（常驻速览）

1. **先成为好老师，才能成为好学生**：自学者的第一步是站到老师视角决定学什么、按什么顺序学。
2. **超前学习**：领先当前阶段提前学后面更难的；用漏斗形深度分层（旧课 100% → 超前层 50% → 30% → 10% → 1%），先抓框架再深入。
3. **范围管理**：第一次只超前一门；宁缺毋滥；先保质保量完成主业（有限游戏），再谈超前。
4. **以教为目的去学**：写讲义、给每个新概念配动机、串讲重排（知识是网状的，讲授必须线性）。
5. **AI 补两个缺口**（找材料 + 及时反馈），但 AI 不是真理机——外部事实必须人工复核，尤其跨书定义冲突。
6. **动机是设计出来的**：认知→心理→行为三层；靠优越感/成就感/自信驱动；日拱一卒把无限游戏切成有限游戏。
7. **反馈必须具体**：泛泛的夸奖与批评都不产生改进；发布要小体量、低姿态起步。

## 学科适用范围（重要，先判断再套用）

本 skill 蒸馏自数学博士的学习讲座，案例全部来自理论数学。**不要对所有学科照搬**：

- **✅ 最适合**：理论型 / 教材型 / 知识点有严格先后依赖 / 有课程学段体系——数学、物理、化学、理论计算机、经济学理论、法学、各类考证。超前学习、抓框架、链条分析、学下一门课这些招就是为它们设计的。
- **⚠️ 部分适用**：依赖链较松的描述性学科（历史、生物、医学基础、语言学）——"抓框架 / 前置知识"仍可用，"超前学习"意义减弱。
- **❌ 不要硬套**：技能型（口语、乐器、游泳、编程实操）、实践/经验型（管理、销售、创业、临床）、艺术创作（写作、绘画、设计）。这些靠"练 / 产出"而非"讲框架"——此时只保留**通用部分**（以教为目的、动机引擎、日拱一卒、反馈管理），**放弃**超前学习与抓框架。

**判停**：用户要学的是技能型/实践型内容、且目标是"尽快上手"时，转到"刻意练习 / 产出导向"的思路，不套本 skill 的规划与超前学习。

## 加载规则

- 每次任务先读本文件，再按路由表加载 **1** 张能力卡；明确跨环节时最多 2 张。
- **先判任务型态**：单轮咨询（问原理/求建议）→ 加载对应卡回答即可；**执行型任务**（"帮我规划/帮我编排/帮我选书"）→ 按卡的 E 步骤实际带用户走完。
- **总控卡优先**：用户说"我想系统学 X、不知道从哪开始"这类整体性问题时，先加载 `learning-loop`，由它决定调用哪张卡，而不是一上来就套某一步。
- 概览/来源类问题用本文件「核心原则」回答，不必加载卡；"超前学习法""日拱一卒"这类**本书概念**的提问，一律用「核心原则」回答，不加载能力卡，也不转 ai-feynman-practice。
- **事前 vs 事后边界**：讲稿还在写/在改（编排与表达、自洽性）→ 本 skill；已经讲出去、翻车后复盘归因（讲砸、讲不清）→ ai-feynman-practice。

## 边界与判停

- 用户要的是**学科知识本身**（"什么是群"）→ 不是本 skill 范围，直接回答或转常规学习。
- 用户要**从零系统学一门新学科** → 本 skill 提供方法，但学科内容需常规学习手段。
- 涉及**情绪/心理困扰**（长期抑郁、严重焦虑）→ 不硬套学习方法论，建议寻求专业帮助。
- 练习与验收问题 → 转 `ai-feynman-practice`。
