# 知识清晰度归因：差距在讲得清，不在记得多

## R — 原文 (Reading)

> 人和人最大的差别不只是知识的存储量，更是知识的清晰度。
>
> — YouCore官方, 《费曼学习法最难的一步，被AI解决了》, 00:43-00:55

## I — 方法论骨架 (Interpretation)

面对"为什么同样学过、结果差距很大"，作者给的归因框架：差异**主要不在记住了多少（存储量），而在概念能否被准确、无空转地讲清楚（清晰度）**。

背后的认知机制（ce09）：记忆分两层——**再认**（看到能认出来）门槛极低，制造"熟悉感"；**自由重建**（不依赖提示自己讲出来）门槛高得多。用"我知道这个概念/我读过"自评理解，本质是用最廉价的认知活动（再认）冒充最昂贵的认知活动（结构化重建）。只有能自由重建（讲得清因果、边界、反例）的知识才算清晰、才可能迁移。

**行动导向**：
① 判断掌握程度，测"能否讲清"而非"能否认出"；
② 补学习短板，先补"讲不清"的部分，而不是继续囤"知道但讲不出"的新知识；
③ 拿同一问题让两个人讲，卡壳处即清晰度短板——可用于评估他人（面试/选人/教学诊断）。

## A1 — 书中的应用 (Past Application)

### 案例：作者"存储了却讲不清"的微波炉瞬间
- **问题**: 作者存储了"微波让水分子高速转向、碰撞生热"（能认出、能复述原话）
- **方法论的使用**: 用"讲清"测试自己的掌握——讲给太太听
- **结论**: 一被问"玻璃碗为什么没事/金属勺为何打火花"就卡壳——存储量够，清晰度不足
- **结果**: 清晰度缺口暴露，才知道自己与"真懂"的差距不在记得少，而在讲不清

## A2 — 触发场景 (Future Trigger) ★

### 用户会在什么情境下需要这个能力?

1. 归因差距：「为什么他学得比我好/我学得比他扎实」
2. 定学习方向：「学习应该往哪使劲」
3. 评估他人：「怎么判断一个人是真懂还是装懂」
4. 反思「知道很多但用不出来」

### 语言信号

- "我知道很多但讲不出来 / 用不出来"
- "为什么同样学，差距这么大"
- "怎么判断掌握程度 / 面试怎么试出真水平"
- "我是不是该学更多，还是把已有的吃透"
- "learning gap / knows a lot but can't explain / mastery vs memorization"

### 与相邻能力的区分

- 与 `understanding-diagnosis`：本卡是**归因口径**（差距从哪来、该练什么），诊断卡是**检测动作**（怎么当场测出清晰度）。用户问"差距哪来的/往哪使劲"走本卡；"测我懂没懂"走诊断卡。
- 与 `three-tier-drill`：本卡回答"练什么"（补清晰度），三档回答"怎么练"。

## E — 可执行步骤 (Execution)

1. **定靶**：让用户挑一个"学过、自认掌握"的领域/概念
   - 完成标准：概念明确

2. **清晰度测试**：不看资料讲一遍（或用 `understanding-diagnosis` 的输出测试），记录卡壳处
   - 完成标准：得到"能认出 vs 能讲清"的差距清单

3. **判定短板类型**：区分——是"知道但讲不清"（清晰度短板，该补）还是"确实不知道"（存储量缺口，该学）
   - 完成标准：短板归类明确

4. **给行动方向**：清晰度短板 → 不继续堆新知识，回头把已学的讲清（转 `three-tier-drill` 练）；存储量缺口 → 正常学习该领域基础
   - 完成标准：用户明确下一步是"补清晰度"还是"补知识量"
   - 判停点：用于评估他人（面试选人）时，第 2 步改为"让被评估者讲，听卡壳处"，完成第 3 步即可

## B — 边界 (Boundary) ★

### 不要在以下情况使用此能力

- 纯**信息积累型任务**（背单词清单、记流程步骤）——它们的差距确实主要在存储量，本框架不适用
- 需要专家级隐性知识评估（清晰度测试测不出"手熟"类能力）

### 作者警告的失败模式

- **以存储量自评理解（ce09）**：能说出术语 ≠ 懂；"我知道"是最廉价的自我证明
- 注意"术语空转"是清晰度不足的典型表现（见 `blind-spot-taxonomy`）

### 作者的盲点 / 局限

- 视频此句紧接机构引流（"能力树/知识体系 SOP"），归因框架本身成立，但作者未展开"如何构建结构化知识"；本卡只取归因口径，不引机构方案
- "清晰度"只覆盖"能讲清"，未覆盖"能用对/做得出"——动手类掌握需另行检验
