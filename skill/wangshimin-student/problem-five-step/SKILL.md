# 五步法

## 触发与不触发

**适用**：遇到任何想不清楚的事，按五步走一遍，避免跳步做无用功。五步是：界定问题 → 构建框架 → 明晰关键 → 高效执行 → 检查调整。任何学段都能用。

**不适用**：考试应试技巧（押题、刷题策略、答题套路）；记忆与遗忘管理（艾宾浩斯、间隔重复、记忆宫殿）；时间管理与日程安排；小组协作与分工。这四类问题本方法答不了。

## 核心原则

1. 跳步是最大的浪费。没界定清楚就动手，越努力越偏。
2. 先想清楚再动手，想的成本远低于返工的成本。
3. "框架"（framework）指拆解问题的结构，是这几张卡共用的母概念。
4. 关键项只占少数，用三要素量表找出影响最大的那一小部分。
5. 每做完一步回头看，结论不成立就退回上一步。

## 执行步骤

1. **界定问题**
   - 完成标准：能用一句话写清"要解决的到底是什么"，并答得出"我的初步想法是不是问题本身"。
2. **构建框架**
   - 完成标准：画出一个能覆盖问题的结构，把各个分支列全。
3. **明晰关键**
   - 完成标准：用占分比、提分难度、遗忘风险给分支排序，圈出关键项。
4. **高效执行**
   - 完成标准：针对关键项写出可执行动作，先做影响最大的一条。
5. **检查调整**
   - 完成标准：每步结束后回看结论是否还成立，不成立就退回上一步。

## 判断标准

| 判断 | 表现 | 结论 |
|---|---|---|
| ok | 五步都有产物，能说清每步的结论 | 做对了 |
| ok | 关键项少而准，精力集中在少数动作上 | 做对了 |
| err | 跳过界定问题直接想方案 | 头步就废，后面全白做 |
| err | 做完不回头检查，错到最后才发现 | 无法定位是哪一步偏的 |
| warn | 框架列了一堆，却不分主次 | 有框架没重点 |
| warn | 走到第三步发现前提就错了 | 退回第一步重界定 |

## 与相邻能力的区分

- 与 `problem-framing`：本 skill 是全程调度，`problem-framing` 是第一步的深挖。问题本身说不清时转它。
- 与 `framework-topdown`：有现成框架可直接套时转它；没有框架、问题也乱时才走本 skill 的头两步。
- 与 `hypothesis-testing`：时间信息充足走本 skill；不足转它的加速版。
- 与 `visualize-content`：本 skill 属分析侧，负责想清楚；`visualize-content` 属表达侧，负责画出来。
- 与 `purposeful-study`：本 skill 解决遇到难事怎么想；`purposeful-study` 解决该学什么。
- 与 `skill-three-types`：本 skill 不判断技能类型，判断入门路径转到 `skill-three-types`。
- 与 `fast-reading`：本 skill 不解决输入，限定时间从书里取信息转到 `fast-reading`。
- 与 `wangshimin-methods`：问两本书本身或未晋级主题，转路由入口。

## 边界

- 本方法来自职场读物，原书案例是职场语境，学生版已改写。
- 考试应试、记忆管理、时间管理、小组协作四类问题答不了。
- 五步不等于必须步步走完，时间不够时可只走前三步。
- ⚠️本书未展开：小学低年级如何把五步压得更短，本包未给做法。
