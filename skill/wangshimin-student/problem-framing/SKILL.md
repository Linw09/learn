# 界定问题

## 触发与不触发

**适用**：动手前先把问题界定清楚，这是防白干的第一道关。没界定好的问题有四类：没能准确描述、没梳理清结构、被表象蒙蔽、忽略隐含假设。全部学段都能用。

**不适用**：考试应试技巧（押题、刷题策略、答题套路）；记忆与遗忘管理（艾宾浩斯、间隔重复、记忆宫殿）；时间管理与日程安排；小组协作与分工。这四类问题本方法答不了。

## 核心原则

1. 笼统的表述不是问题。"我数学不好"要拆成哪类题、错在哪一步。
2. 初步解决方案不等于问题本身。想换座位，真问题可能是看不见黑板。
3. 表象背后有根因，对同一个现象连问五次为什么。
4. 隐含假设藏得最深，分环境假设、时间假设、理论前提三类。
5. 结构用 5W2H 梳理：Why、What、When、Where、Who、How、How much。

## 执行步骤

1. **准确描述**
   - 完成标准：把笼统说法拆成具体的错点和步骤，能指出错在哪类题、哪一步。
2. **梳理结构**
   - 完成标准：用 5W2H 逐项写清任务要求，七项都有答案或标"待查"。
3. **追问根因**
   - 完成标准：对现象连问五次为什么，追到一条能动手改的原因。
4. **列隐含假设**
   - 完成标准：环境、时间、理论前提三类各写出至少一条。
5. **区分方案与问题**
   - 完成标准：能写出一句纯问题，句中不含任何做法。

## 判断标准

| 状态 | 表现 |
|---|---|
| ok | 问题能用一句话说清，且不含做法 |
| ok | 根因追到能动手改的一层 |
| ok | 三类隐含假设都摆到了桌面上 |
| warn | 把"我想怎么做"当成问题 |
| warn | 停在表象，没问为什么 |
| warn | 假设没写出来，却当成事实用 |

## 与相邻能力的区分

- 与 `problem-five-step`：本 skill 是它第一步的深挖。要的是全程调度时转 `problem-five-step`。
- 与 `framework-topdown`：`framework-topdown` 适用于已有现成框架可用的场景；本 skill 适用于连问题都还没界定清楚的场景。
- 与 `hypothesis-testing`：本 skill 只负责把问题说清；要快速下假设去验证转 `hypothesis-testing`。
- 与 `visualize-content`：本 skill 属分析侧，负责界定；`visualize-content` 属表达侧，负责画图。
- 与 `purposeful-study`：本 skill 界定当下这个问题；该学什么范围转 `purposeful-study`。
- 与 `skill-three-types`：判断技能类型与入门路径转 `skill-three-types`。
- 与 `fast-reading`：限定时间从书里取信息转 `fast-reading`。
- 与 `wangshimin-methods`：问两本书本身或未晋级主题，转路由入口。

## 边界

- 本方法来自职场读物，原书案例是职场语境，学生版已改写。
- 考试应试、记忆管理、时间管理、小组协作四类问题答不了。
- 界定问题不是无限深挖，能动手改就到头，别陷进追问。
- ⚠️本书未展开：界定到什么颗粒度算够，本包未给量化标准。
