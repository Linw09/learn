# 界定问题：把"问题到底是什么"说实

## R — 原文 (Reading)

原书把"发现—界定问题"放在解决问题第一步，并指出真正的问题常以三种伪装出现：问题的表象、初步解决方案、无关的干扰信息。
> "真正的问题并不会自动摆在你的面前"（P47-65）

原书归纳出四类界定不清，并给出相应工具：准确描述、理清结构、探究本质、显性化隐含假设。

## I — 解释 (Interpretation)

四类界定不清与对应工具：
1. 没能准确描述——"我数学不好"太粗，改成"哪类题错率高、错在哪个步骤"。
2. 没梳理清楚结构——用 5W2H 把任务要求拆全。
3. 被表象蒙蔽——用 5Why 连问五次追根因。
4. 忽略隐含假设——分环境假设、时间假设、理论前提三种。

5W2H：Why / What / When / Where / Who / How / How much。
核心判断：**初步解决方案 ≠ 问题本身**，先分清再动手。

## A1 — 书中的例子 (Past Application)

### 案例 1：把"我数学不好"改准（类型①）
- ⚠️原书案例为职场语境，此处改写。
- 问题：一句"我数学不好"没法解决。
- 用法：改成"函数题错率最高，错在化简这一步"。
- 结论：描述具体到对象、现象、范围，才能动手。

### 案例 2：成绩下滑连问五次（类型③）
- ⚠️原书案例为职场语境，此处改写。
- 问题：成绩突然下滑。
- 用法：5Why 连问——不是不努力 → 刷题量上去了 → 但没整理错题 → 错了只对答案 → 不看解析所以下次还错。
- 结论：根因是不看解析，不是不够努力。
- 结果：改的是"看解析"这一步，不是加题量。

### 案例 3：要换座位（初步方案 ≠ 问题本身）
- ⚠️原书案例为职场语境，此处改写。
- 问题：一心想"换座位"。
- 用法：追问换座位的理由，真问题是"坐在原位看不见黑板"。
- 结论：换座位只是初步方案，可能换到哪都看不清。
- 结果：真正要解决的是看得见黑板，配眼镜或调前排都行。

## A2 — 什么时候用 (Future Trigger)

### 用户会在什么情境下需要
1. "我数学不好 / 我英语差"这类说不清的问题。
2. 一上来就想要做法，却说不出要解决什么。
3. 手上有个方案，不知道它是不是真问题。

### 语言信号
- "我就是……不好 / 反正就是不行"
- "我想……（某个做法）"
- "问题到底是啥 / 我是不是搞错了"

### 与相邻能力的区分
- 与 problem-five-step：本卡只做它第一步的深挖。
- 与 framework-topdown：问题没界定清楚时用本卡，已有现成框架可直接套时才用后者。

## E — 可执行步骤 (Execution)

1. 重写问题
   - 完成标准：问题里出现具体对象、现象、范围，不出现"不好""差"这类评价词。
2. 用 5W2H 拆任务
   - 完成标准：七问都能填出内容，填不出的标"待查"。
3. 用 5Why 追根因
   - 完成标准：问到出现可以动手改的具体环节为止。
4. 列出隐含假设
   - 完成标准：环境 / 时间 / 理论前提各写一条，每条写出"它若不成立会怎样"。
5. 分辨方案与问题
   - 完成标准：能写出"我真正要解决的是______"，且与初步方案不是同一句。

## B — 边界 (Boundary)

### 原书边界
- 5Why 依赖对原因的了解，了解太浅时会停在表象层。
- 隐含假设一旦列全，问题篇幅会变长；不是每个问题都值得做全套。

### 这套方法答不了的四类学生场景
- 考试应试技巧：押题、刷题策略、答题套路。
- 记忆与遗忘管理：艾宾浩斯、间隔重复、记忆宫殿。
- 时间管理与日程安排。
- 小组协作与分工。
遇到以上场景，明说"这套方法解决不了你的问题"，不要硬套。

- 学段：全部。
