# 三层次技能分类：先判断学的是哪一类，再选路径

## R — 原文 (Reading)

原书发现很多人学得慢，是因为不区分技能类型，用同一种办法对付所有技能。理解性技能此处的关键提醒是：
> "一定要严格按照这个框架的内容和使用要求生搬硬套"（P293-316）

原书按技能性质分三类，各自给出不同的入门步骤，并另给一条进入新领域的通用路径。

## I — 解释 (Interpretation)

这是学习侧的分派器：判断学的属于哪一类，选对应路径。

1. **程序性认知技能**（先理解再练熟练度：编程、乐器操作、表格软件、书法基础）
   → 四步：基本了解 → 简单入门 → 迭代深化 → 自然重复。
2. **理解性认知技能**（概念为主、讲规律：历史因果、科学概念、文学分析、经济学）
   → 三步：挑框架 → 第一次严格照框架用 → 质疑改进。
3. **行为技能**（身体熟练度：游泳、跳绳、投篮、体能）
   → 四步：挑对象 → 量力模仿 → 分解简化 → 局部细化。

**跨学科入门五步**（原书"切入新行业五步法"改造）：构建框架 → 比对迁移 → 功利取舍 → 整体应用 → 改进迭代。
三个陷阱：硬套别的学科的方法、把自己当白纸、贪大求全。

改名理由：⚠️原书为职场语境，学生场景为改写。原书这一节面向离开原职业、进入新领域的人；学生只换学科，不换职业，所以改名为"跨学科入门"。

## A1 — 书中的例子 (Past Application)

### 案例 1：文科生跨到统计
- ⚠️原书案例为职场语境，此处改写。
- 问题：学统计时想用背历史的方法，背定义。
- 用法：比对迁移——统计要靠练题和看数据分布，不是背。
- 结论：先找两门学科的相同与不同，再决定怎么学。

### 案例 2：物理生跨到编程
- 问题：物理很好，但一上手编程就卡住。
- 用法：按程序性认知技能四步，先跑通最简单的一段程序。
- 结论：编程靠迭代练，不靠先看完整本书。

### 案例 3：贪大求全
- 问题：想一次把新学科的全部内容学完。
- 用法：第一轮只搭框架，之后逐步加。
- 结论：贪大求全会让人卡在开头。

## A2 — 什么时候用 (Future Trigger)

### 用户会在什么情境下需要
1. 要开始学一门新技能，不知道从哪入手。
2. 学了很久还是不会用。
3. 从一门学科跨到另一门学科。

### 语言信号
- "怎么学编程 / 怎么学乐器 / 怎么学游泳"
- "我该先看书还是先练 / 从哪开始学"
- "我是文科的，怎么学理科 / 跨学科怎么入门"

### 与相邻能力的区分
- 与 purposeful-study：本卡决定用什么路径学，后者决定学什么范围。
- 与 fast-reading：本卡是路径选择，后者是其中一种输入方式。

## E — 可执行步骤 (Execution)

1. 判断技能类型
   - 完成标准：能说出学的是三类中的哪一类，并写出判断依据。
2. 选对应路径
   - 完成标准：按该类路径列出第一步行什么。
3. 走该类路径
   - 完成标准（程序性）：能不看教程独立做一遍最简单版本。
   - 完成标准（理解性）：能用框架讲清一个完整案例。
   - 完成标准（行为）：能完成分解后的单个动作。
4. 跨学科时防灾
   - 完成标准：写下并逐条排除三个陷阱（硬套、当白纸、贪大求全）。

## B — 边界 (Boundary)

### 原书边界
- 原书场景面向成年读者，本卡已改名为"跨学科入门"。
- 三类之间可能重叠；分不清时按主要的性质归类，别纠结。

### 这套方法答不了的四类学生场景
- 考试应试技巧：押题、刷题策略、答题套路。
- 记忆与遗忘管理：艾宾浩斯、间隔重复、记忆宫殿。
- 时间管理与日程安排。
- 小组协作与分工。
遇到以上场景，明说"这套方法解决不了你的问题"，不要硬套。

## 相关能力

- 学段：全部。
