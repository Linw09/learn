# 自上而下选用框架：四步拆解一个问题

## R — 原文 (Reading)

原书对比了两种构建框架的路子，主张能选现成框架就别每次从头提炼。
> "站在巨人的肩膀上，直接选用已有的框架"（P90-106）

原书同时点明代价：选框架要求熟练与经验，选错了框架反而误导思考。

## I — 解释 (Interpretation)

四步：
1. 选择框架——从储备的框架里挑一个合适的。
2. 分解问题——按框架的逻辑把问题拆到可动手。
3. 多维思考——用换位 / 逆向 / 零基补出原来看不到的点。
4. 检查框架——用 MECE 检查，重点是"不重"。

学生能用的框架库，分三类用途。

**描述一件事的组成**（原书表 3.7.1，P163）：Why-What-How（为什么、是什么或做什么、怎么做）、过去现在未来、少年中青年老年、大中小、个人家庭社会、乐观客观悲观。

**看一件事怎么发展**：开始执行收尾、前期中期后期。

**比两件事的差别或追原因**：对比表、优缺点列表、五要素（人物/时间/地点/起因/结果）、SWOT、因果链（鱼骨图）。

原书把这张表定位成"供参考，以便举一反三"，并建议读者"多积累一些你自己常用的框架"，所以它是起步不是定规。

⚠️ 原书同表第 7 条是 3C 战略三角（Corporation / Customer / Competitor），企业战略术语，学生用不上，未收录。
多维思考三招是公开的思维工具，非本书原创。
检查框架的例外：**只查"不重"，重要性顺序不查"不漏"**。

## A1 — 书中的例子 (Past Application)

### 案例 1：手机校园卡要不要换（4P 案例学生版）
- ⚠️原书案例为职场语境，此处改写。
- 问题：现有校园卡要不要换成新出的一款。
- 用法：选对比表框架，列月租、流量、信号、合约期四栏。
- 结论：多维思考补盲——换位（问被换掉的一方怎么想）、逆向（怎样保证换了更亏）、零基（抛开"想换"重来比一次）。
- 结果：按四个维度打分，而不是凭一时冲动决定。

### 案例 2：社团招新没人来
- 问题：招新摆摊三天，报名寥寥。
- 用法：选因果链（鱼骨图）框架，从宣传、时间、地点、吸引力四支拆。
- 结论：拆开后发现主因是摆摊时间撞了月考。
- 结果：换时间后报名回升。

## A2 — 什么时候用 (Future Trigger)

### 用户会在什么情境下需要
1. 手里有一个框架或表格，想快速把一件事拆开。
2. 需要一张图讲清一件事的组成。
3. 做选择时想比一比对，而不是凭感觉。

### 语言信号
- "有没有现成的表 / 框架 / 模型可以用"
- "怎么拆 / 从哪几个维度看 / 列个表对比"
- "用什么框架分析这个"

### 与相邻能力的区分
- 与 problem-framing：连问题都没界定清楚时先转 problem-framing。
- 与 hypothesis-testing：本卡是拆解，后者是先用假设缩小范围。

## E — 可执行步骤 (Execution)

1. 选择框架
   - 完成标准：从框架库里挑出一个，并说出它为什么适合这个问题。
2. 分解问题
   - 完成标准：把问题填进框架的每个格子，格子填不满就换框架。
3. 多维思考
   - 完成标准：至少用换位 / 逆向 / 零基中的一招，补出原来看不到的 1 个点。
4. 检查框架
   - 完成标准：只查"不重"——各分支是否互相包含；顺序是否按重要性排列。

## B — 边界 (Boundary)

### 原书边界
- 选框架依赖储备与经验，框架不熟时会挑错。
- 框架都有应用前提，前提变了要先改框架再用。

### 这套方法答不了的四类学生场景
- 考试应试技巧：押题、刷题策略、答题套路。
- 记忆与遗忘管理：艾宾浩斯、间隔重复、记忆宫殿。
- 时间管理与日程安排。
- 小组协作与分工。
遇到以上场景，明说"这套方法解决不了你的问题"，不要硬套。

## 相关能力
- depends-on：problem-framing（先把问题界定清楚）。
- composes-with：problem-five-step（本卡是其第二步）、hypothesis-testing（用框架框定假设范围）。
- 学段：初中以上。小学不做，框架对小学偏抽象。
