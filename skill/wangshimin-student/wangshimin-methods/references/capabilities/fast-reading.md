# 整体阅读与多重阅读：限定时间内拿到自己要的那部分

## R — 原文 (Reading)

原书主张先按阅读目的选方法，再动手读；速度不是关键，理解与加工才是。
> "以能看清每页的内容为标准"（P111-135）

原书给两种主方法加一种补充：只取少数信息用整体阅读，系统学用多重阅读，跨材料用主题阅读。

## I — 解释 (Interpretation)

**整体阅读五步**（适合只想要 1-3 个有用信息）：
1. 定目的——解决什么问题、解决到什么程度。
2. 提出具体问题——把目的转成向作者的具体提问，拒绝"如何变厉害"这类模糊问题。
3. 选关键词句——最多 16 个，超了删或换。
4. 挑三个关键点——直接选三个核心，或把关键词归类汇总成三个。
5. 归纳成一句话结论。

**多重阅读四步**（适合系统学）：
1. 明确目的；2. 画出框架；3. 变速阅读；4. 重点精读并归入自己的知识体系，**不照抄书的顺序**。
变速阅读四种处理：不相关跳过 / 熟悉的最快扫 / 不熟的正常读且每章停下回忆 / 难的标记略读。

**主题阅读两步**：先搭主题框架，再按图索骥填材料。
⚠️原书标题"一天读上百份资料"为夸大表述，此处不保留该量化承诺。

明确一点：这套方法**不教你怎么记住内容**，只教你限定时间内拿到需要的部分。记忆管理不在范围内。

## A1 — 书中的例子 (Past Application)

### 案例 1：读教材取一个知识点
- ⚠️原书案例为职场语境，此处改写。
- 问题：要在教材里找"某个实验为什么这样做"。
- 用法：定目的 → 写具体问题 → 扫出十几个关键词句 → 归纳一句话。
- 结论：不用从头读完整章。

### 案例 2：读课纲
- 问题：拿到一份课纲，想知道整门课的骨架。
- 用法：多重阅读——先画框架，再变速读。
- 结论：框架先立起来，细节后面填。

### 案例 3：读科普书
- 问题：系统了解一个主题，材料不止一本。
- 用法：主题阅读——先搭主题框架，再按图索骥填。
- 结论：有框架才不会越读越乱。

## A2 — 什么时候用 (Future Trigger)

### 用户会在什么情境下需要
1. 时间有限，只想从书里拿到一两个答案。
2. 要系统学一本书，但不想从头顺读。
3. 围绕一个主题看多份材料。

### 语言信号
- "没时间读完 / 只想找某一部分"
- "怎么快速看懂一本书 / 老师给的资料好多"
- "围绕某主题找资料"

### 与相邻能力的区分
- 与 purposeful-study：本卡是输入方式，后者是学习决策，先由后者定"学什么"。
- 与 skill-three-types：本卡只解决读，不解决学哪种技能。

## E — 可执行步骤 (Execution)

1. 定目的
   - 完成标准：写出要解决什么问题、解决到什么程度。
2. 提具体问题
   - 完成标准：把目的转成向作者的具体提问，不写模糊问题。
3. 选关键词句
   - 完成标准：关键词句不超过 16 个，超了删或换。
4. 挑三个关键点
   - 完成标准：直接选三个，或把关键词归类汇总成三个。
5. 归纳一句话结论
   - 完成标准：用一句话写出结论，并能回答第 1 步的目的。
6. 系统学时改走多重阅读
   - 完成标准：画出框架，按熟悉度变速读，重点处精读并归入自己的体系。

## B — 边界 (Boundary)

### 原书边界
- 整体阅读只适合取少数信息，不适合系统掌握一门学问。
- 不保留"一天读上百份资料"的量化承诺；不提供记忆方法。

### 这套方法答不了的四类学生场景
- 考试应试技巧：押题、刷题策略、答题套路。
- 记忆与遗忘管理：艾宾浩斯、间隔重复、记忆宫殿。
- 时间管理与日程安排。
- 小组协作与分工。
遇到以上场景，明说"这套方法解决不了你的问题"，不要硬套。
