# 问题解决五步法：界定问题 → 构建框架 → 明晰关键 → 高效执行 → 检查调整

## R — 原文 (Reading)

原书用导入案例说明漏掉第一步的代价。手机企业反映"招不到普工"，若直接分析招聘渠道，报告再漂亮也没用。
追问后才发现：计划招 200 人，前半月已招到 180 人，只是剩下 20 人没招到。
> "确实是招不到普工，只是这个'招不到'与你想的不一样"（P42-46）

据此原书把解决问题拆成五步，强调先把问题定义对，再谈方案。

## I — 解释 (Interpretation)

五步环环相扣，前一步的产出是后一步的输入：
1. 界定问题——说清"要解决什么"，别把表象或初步方案当问题。
2. 构建框架——用框架把问题拆成可分析的部分（"框架"母概念归本卡）。
3. 明晰关键——在拆分结果里挑出最该先动的少数部分。
4. 高效执行——按优先级做，不求一次做全。
5. 检查调整——看结果是否真解决了问题，不对就回到前一步。

什么时候该用：事情"想不清楚"就用；已经清楚只需执行，不必走全程。

## A1 — 书中的例子 (Past Application)

### 案例 1：竞赛报名没名额（导入案例学生版）
- ⚠️原书案例为职场语境，此处改写。
- 问题：报名参加竞赛，结果被告知没名额。
- 用法：若一上来只想"怎么改报名方式"，只能得一半分。
- 结论：没先搞清是差 1 个名额还是差 20 个，方案就是空转。
- 结果：先界定"差多少、卡在哪一环"，再决定争名额还是换赛道。

### 案例 2：值日表总有人漏做
- 问题：值日表排了，却总有人漏做。
- 用法：界定问题（是排班不合理，还是没人提醒）→ 构建框架（按人头、按时间、按任务拆）→ 明晰关键（挑最常出错的时段）。
- 结论：先定位漏做发生在哪一环，再改规则。
- 结果：改的是那一个环节，不是重排整张表。

## A2 — 什么时候用 (Future Trigger)

### 用户会在什么情境下需要
1. "这事我想不清楚，不知道从哪下手。"
2. "这事我想从头理一遍。"值日表老有人漏做、班费账目对不上、论文选题太宽。
3. 小组实验总做不成、社团招新没人来。

### 语言信号
- "从哪开始 / 先做什么 / 一团乱 / 理不清"
- "选题太宽 / 实验做不成 / 招不到人 / 账对不上"

- 与 problem-framing：本卡是全程调度，后者的深挖只用在第一步。

## E — 可执行步骤 (Execution)

1. 界定问题
   - 完成标准：用一句话写出"要解决什么"，句子里不含任何做法。
2. 构建框架
   - 完成标准：画出一张拆解图，每个分叉都能答"这是问题的哪一块"。
3. 明晰关键
   - 完成标准：用占分比 / 提分难度 / 遗忘风险三要素排序，选出最先要动的 1-2 块。
4. 高效执行
   - 完成标准：只做排序靠前的部分，并记下做了什么、结果如何。
5. 检查调整
   - 完成标准：对照第 1 步写一句"解决了吗"；没有就回到对应步骤重来。

## B — 边界 (Boundary)

### 原书边界
- 原书面向职场场景，导入案例与排序量表均为企业口径，本卡已换成学生口径。
- 五步法假设你能拿到足够信息；信息严重不足时它反而慢。

### 这套方法答不了的四类学生场景
- 考试应试技巧：押题、刷题策略、答题套路。
- 记忆与遗忘管理：艾宾浩斯、间隔重复、记忆宫殿。
- 时间管理与日程安排。
- 小组协作与分工。
遇到以上场景，明说"这套方法解决不了你的问题"，不要硬套。
