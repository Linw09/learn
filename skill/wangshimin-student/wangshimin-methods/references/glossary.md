# GLOSSARY — 《思维力》《学习力》

> 跨卡共享术语词典。所有能力卡统一按本表用法理解这些词，不使用通用义。
> 未标出处的条目为本 pack 学生版改写口径。

| 术语 | 书中用法 | 和通用义的差异 | 主要使用 skill |
|---|---|---|---|
| 框架 | 对系统构成元素及元素间联系的简化体现 | 不是"套路模板"；是理解与拆解问题的骨架 | problem-five-step（母概念归口） |
| 系统思维 | 用框架来系统思考和表达的思维方式 | 不等于"想得全面"；核心是把对象当系统拆 | problem-five-step |
| 界定问题 | 解决问题第一步，说清"要解决什么" | 不等于复述现象；要排除表象与初步方案 | problem-framing |
| 隐含假设 | 未明说却被当作成立的前提 | 不是"我没说但我知道"；是没意识到的默认 | problem-framing |
| MECE | 相互独立、完全穷尽的分组要求 | 本 pack 检查框架时只查"不重"，重要性顺序不查"不漏" | framework-topdown |
| 四种逻辑顺序 | 时间顺序 / 结构顺序 / 重要性顺序 / 演绎顺序 | 不是任意排序；每种对应不同的组织依据 | framework-topdown |
| 多维思考 | 换位 / 逆向 / 零基三招 | 三招是公开思维工具，非本书原创 | framework-topdown |
| 换位思考 | 换成被评价的人会怎么看 | 不是"替别人着想"的口号；是换视角补信息 | framework-topdown |
| 逆向思考 | 反过来问"怎样保证失败" | 不是悲观；是用反向问题暴露盲点 | framework-topdown |
| 零基思考 | 抛开已知结论从头再来 | 不是清零重学；是暂时搁置既有判断 | framework-topdown |
| 假设思考 | 先下结论再验证，倒着走 | 不是拍脑袋；要"有框架地蒙" | hypothesis-testing |
| QDT | Quick and Dirty Test，几分钟快速粗略验证 | ⚠️原书未给出处；只做粗略判断不做严谨结论 | hypothesis-testing |
| 80/20 | 少数关键因素决定多数结果 | 是公开知识，非本书原创；用于挑"明晰关键"的部分 | problem-five-step |
| 功利性学习 | 从真实需要出发，学完立马用 | 不是"有用才学"的功利；是用任务带动学习 | purposeful-study |
| 最简应用 | 先抓主干，在最简单条件下跑通核心功能 | 不是偷懒；是降低入门难度再逐条加条件 | purposeful-study |
| 自然重复 | 把跑通流程做成模板或清单，下次直接套用 | 不是死记硬背；是让使用本身带来重复 | purposeful-study |
| 三层次技能分类 | 程序性认知技能 / 理解性认知技能 / 行为技能 | 不是按学科分；是按技能性质分 | skill-three-types |
| 程序性认知技能 | 先理解再练熟练度的技能 | 不等于"动手操作"；编程、乐器、表格软件都算 | skill-three-types |
| 理解性认知技能 | 概念为主、讲规律的技能 | 不等于"背书"；要能用框架讲清规律 | skill-three-types |
| 行为技能 | 靠身体熟练度的技能 | 不等于"体育课"；游泳、跳绳、投篮、体能都算 | skill-three-types |
| 整体阅读 | 五步从一本书里取 1-3 个有用信息 | 不是速读比赛；以能看清每页为标准 | fast-reading |
| 多重阅读 | 四步系统吸收一本书的精华 | 不是精读到底；按熟悉度变速处理 | fast-reading |
| 变速阅读 | 按熟悉度分四种速度处理材料 | 不是一直慢读；不相关跳过、熟悉快扫 | fast-reading |
| 主题阅读 | 先搭主题框架再按图索骥填材料 | 不是随便多读几本；先有框架再找材料 | fast-reading |
| 自然学习设计 | ⚠️原书引用；把学习放进真实任务、在使用中自然完成的整体安排 | 术语来自原书，非本 pack 发明 | purposeful-study |
| 自上而下 | 先选现成框架再往里填 | 与自下而上相对；要求有框架储备 | framework-topdown |
| 自下而上 | 先归纳素材再提炼成框架 | 与自上而下相对；耗时但贴合具体情况 | framework-topdown |
| 明晰关键 | 在拆分结果里挑最该先动的少数部分 | 学生口径用占分比 / 提分难度 / 遗忘风险排序 | problem-five-step |
| 问题表象 | 问题表现出来的样子，不一定是根因 | 与根本原因相对；追根因用 5Why | problem-framing |
| 初步解决方案 | 第一反应想到的做法，容易被当成问题本身 | 本 pack 强调"初步方案 ≠ 问题本身" | problem-framing |
