# 把内容画成图

## 触发与不触发

**适用**：把想清楚的内容变成一张图，一图胜过千字。属表达侧。适合小学高年级起。

**不适用**：考试应试技巧（押题、刷题策略、答题套路）；记忆与遗忘管理（艾宾浩斯、间隔重复、记忆宫殿）；时间管理与日程安排；小组协作与分工。这四类问题本方法答不了。

## 核心原则

1. 内容没想清楚就别画，图只是把已想清的东西摆出来。
2. 先搭表达框架，再挑图表，最后填元素，顺序不能倒。
3. 学生能用的图有：时间轴、对比表、流程图、结构树、因果图、思维导图、坐标图、数据图表（柱/折/饼）。
4. 填什么看 5W2H：What/Who 用图形或图标，Why 用因果图，When 用时间轴。
5. 继续对应：How 用流程图，Where 用地图或区域图，How much 用柱图、折线图、饼图。
6. 左右脑、格式塔这类理论依据只用一句带过，学生用不到。

## 执行步骤

1. **构建表达框架**
   - 完成标准：先写清这张图要让人看懂什么，列出要放进图里的内容。
2. **选择图表结构**
   - 完成标准：对照 5W2H 挑出合适的图型，说清为什么选它。
3. **填充元素**
   - 完成标准：每个元素都归位到对应图型，图上没有多余也看不出缺漏。

## 判断标准

| 状态 | 表现 |
|---|---|
| ok | 先有表达框架，再选图型 |
| ok | 图型与内容对得上，一眼看得懂 |
| ok | 元素不多不少，都归了位 |
| warn | 内容自己都没想清就开始画 |
| warn | 图型选得花哨，却对不上内容 |
| warn | 元素堆了一堆，看不出重点 |

## 与相邻能力的区分

- 与 `problem-five-step`：本 skill 属表达侧；`problem-*` 三个属分析侧，负责把内容想清楚。
- 与 `problem-framing`：本 skill 不界定问题，问题没说清转 `problem-framing`。
- 与 `framework-topdown`：本 skill 不拆解问题，要用现成框架拆解转 `framework-topdown`。
- 与 `hypothesis-testing`：本 skill 不下判断，时间不足要快速判断转 `hypothesis-testing`。
- 与 `purposeful-study`：本 skill 只负责表达，该学什么转 `purposeful-study`。
- 与 `skill-three-types`：判断技能类型与入门路径转 `skill-three-types`。
- 与 `fast-reading`：限定时间从书里取信息转 `fast-reading`。
- 与 `wangshimin-methods`：问两本书本身或未晋级主题，转路由入口。
