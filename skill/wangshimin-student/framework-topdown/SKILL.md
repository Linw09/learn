# 用框架自上而下拆解

## 触发与不触发

**适用**：用现成的分析框架快速拆解一个问题，站在现成肩膀上。适合初中以上；框架对小学偏抽象，小学不做。

**不适用**：考试应试技巧（押题、刷题策略、答题套路）；记忆与遗忘管理（艾宾浩斯、间隔重复、记忆宫殿）；时间管理与日程安排；小组协作与分工。这四类问题本方法答不了。

## 核心原则

1. 先挑框架再拆问题，别对着问题硬想。
2. 学生能用的框架有：时间线、五要素（人物/时间/地点/起因/结果）、对比表、因果链（鱼骨图）、优缺点列表、SWOT。
   - "框架"（framework）的定义见 `problem-five-step`，本卡只管挑和用，不重新定义。
3. 多维思考三招是换位、逆向、零基。这三招是公开的思维工具，非本书原创。
4. 换位是换成被评价者的角度看；逆向是反过来问"怎样保证失败"；零基是抛开已知结论重来。
5. 检查框架用 MECE，但只查"不重"；重要性顺序不查"不漏"，这是原书明确的例外。

## 框架库

挑框架时从这里选。原书把这张表定位成「供参考，以便举一反三」——它是**现成的切分角度**，不是必须遵守的固定模板。

**描述一件事的组成**
- Why-What-How：为什么、是什么或做什么、怎么做
- 过去、现在、未来
- 少年、中青年、老年（人口结构）
- 大、中、小
- 个人、家庭、社会（社会议题）
- 乐观、客观、悲观（评价一件事的三种立场）

**看一件事怎么发展**
- 开始、执行、收尾
- 前期、中期、后期

**比两件事的差别**
- 对比表、优缺点列表、五要素（人物/时间/地点/起因/结果）、SWOT

**追一件事的原因**
- 因果链（鱼骨图）

作者自己也建议「多积累一些你自己常用的框架」。上表是起步，不是终点。

⚠️ 原书表 3.7.1 第 7 条是 3C 战略三角（Corporation / Customer / Competitor），属企业战略术语，学生用不上，未收录。

## 执行步骤

1. **选择框架**
   - 完成标准：从框架库里挑出一个能装下这个问题的框架，说清为什么选它。
2. **分解问题**
   - 完成标准：框架的每个格子都填上内容，问题被拆成若干小块。
3. **多维思考**
   - 完成标准：至少用换位、逆向、零基中的一招，得到新的看法。
4. **检查框架**
   - 完成标准：用 MECE 检查各块是否"不重"，重了就合并。

## 判断标准

| 状态 | 表现 |
|---|---|
| ok | 框架与问题匹配，拆出的块能对上问题 |
| ok | 至少换过一个新角度，结论有变化 |
| ok | 各块之间不重叠 |
| warn | 硬套一个不合适的框架 |
| warn | 只用了正向视角，没换位也没逆向 |
| warn | 各块互相重叠，同一件事数了两遍 |

## 与相邻能力的区分

- 与 `problem-framing`：`framework-topdown` 适用于已有现成框架可用的场景；`problem-framing` 适用于问题都还没界定清楚的场景。
- 与 `problem-five-step`：本 skill 只做"构建框架"这一步；要走全程五步转 `problem-five-step`。
- 与 `hypothesis-testing`：本 skill 是顺向拆解；时间信息不足、要先下结论的转 `hypothesis-testing`。
- 与 `visualize-content`：本 skill 属分析侧，负责拆解；`visualize-content` 属表达侧，负责把结果画出来。
- 与 `purposeful-study`：本 skill 拆的是眼前这个问题；该学什么转 `purposeful-study`。
- 与 `skill-three-types`：判断技能类型与入门路径转 `skill-three-types`。
- 与 `fast-reading`：限定时间从书里取信息转 `fast-reading`。
- 与 `wangshimin-methods`：问两本书本身或未晋级主题，转路由入口。

## 边界

- 本方法来自职场读物，原书案例是职场语境，学生版已改写。
- 考试应试、记忆管理、时间管理、小组协作四类问题答不了。
- 小学不做，框架对小学偏抽象。
- ⚠️换位、逆向、零基三招为公开思维工具，非本书原创。
